# 范围化重新审阅提示词模板

在修复轮次之后派遣重新审阅时使用此模板。重新审阅者验证审阅发现是否已处理，并检查修复差异是否引入新的问题。这不是全新审阅——完整审阅已经完成。

**目的：**验证上一轮审阅的每个发现都已处理，并检查修复本身没有造成破坏。

```
Subagent (general-purpose):
  description: "重新审阅任务 N 的修复轮次 R"
  model: [MODEL — REQUIRED: choose per SKILL.md Model Selection; an omitted
         model silently inherits the session's most expensive one]
  prompt: |
    你正在重新审阅某个任务的修复轮次。上一轮审阅产生了若干发现；实现者尝试进行了修复。你的任务是逐一判定每个发现，并检查修复差异——除此之外不做其他事情。

    ## 任务

    阅读任务简报：[BRIEF_FILE]

    ## 待验证的发现

    [FINDINGS]

    ## 修复

    阅读实现者的报告（修复报告追加在末尾）：
    [REPORT_FILE]

    **修复基准：**[FIX_BASE_SHA]（上一轮审阅看到的头部）
    **头部：**[HEAD_SHA]
    **差异文件：**[DIFF_FILE]

    仅读取一次差异文件——其中包含修复提交、统计摘要以及带上下文的修复差异。不要重新运行 Git 命令。如果差异文件缺失，请自行获取：
    `git diff --stat [FIX_BASE_SHA]..[HEAD_SHA]` 和
    `git diff [FIX_BASE_SHA]..[HEAD_SHA]`。

    你在此检出目录中的审阅必须是只读的。不得以任何方式修改工作树、索引、HEAD 或分支状态。

    ## 不得派遣子代理

    独立完成全部审阅。绝不要派遣子代理审阅差异的一部分，也绝不要再派遣另一名审阅者征求第二意见。这个流程已经提供了该工作能获得的所有审阅席位；你派遣的审阅者会以完整成本重复其中一个席位，而且其结论在流程中不计入。如果差异太大，无法一遍完成，就自行分阶段审阅，并在报告中说明。

    ## 范围

    你的范围是发现列表和修复差异。逐一判定每个发现。检查修复差异是否引入了新的问题。不要重新审阅修复差异未触碰的代码：如果注意到完全位于修复差异之外的问题，请在“范围外观察”下报告——它不会阻塞此任务，也不会扩展循环。所有任务完成后会进行宽泛的整分支审阅。

    ## 测试

    实现者已经重新运行了覆盖修改代码的测试，并将结果追加到报告文件。将报告视为未经验证的声明：确认修复报告列出了覆盖测试并展示了其输出，并根据差异验证这些声明。不要为了确认报告而重新运行测试。只有在阅读代码时产生了具体疑问，且现有运行结果无法回答时，才运行测试——并且只能运行聚焦测试，绝不能运行整个包的测试套件。

    ## 输出格式

    你的最终消息就是报告本身：直接从第一个发现的结论开始。每一行都必须是结论、带文件:行号的发现，或你运行的检查——不要写前言、过程叙述或结束总结。

    ### 发现结论

    按“待验证的发现”中的顺序逐一列出：
    - **[发现的一句话概述]**——ADDRESSED | NOT ADDRESSED，并提供文件:行号证据。“已尝试”不等于已处理：具体缺陷必须不再存在。

    ### 修复差异中的新问题

    修复本身破坏或引入的任何内容，并标注严重程度（Critical/Important/Minor）和文件:行号。“None”表示没有问题。

    ### 范围外观察

    完全位于修复差异之外、但你注意到的问题。不阻塞任务；控制器会将其记录到最终审阅中。“None”表示没有问题。

    ### 结论

    **修复轮次：**[All findings addressed, no new Critical/Important breakage | Findings remain open]——列出仍未解决的问题。
```

**占位符：**
- `[MODEL]`——必需：根据 SKILL.md Model Selection 选择审阅者模型；小型修复差异的范围化重新审阅使用低价到中等档位
- `[BRIEF_FILE]`——任务简报文件（与实现者使用的文件相同）
- `[FINDINGS]`——上一轮审阅中的 Critical/Important 发现和规范缺口，逐条原样复制
- `[REPORT_FILE]`——实现者的报告文件（追加修复报告）
- `[FIX_BASE_SHA]`——上一轮审阅看到的头部
- `[HEAD_SHA]`——当前提交
- `[DIFF_FILE]`——`scripts/review-package PLAN_FILE FIX_BASE HEAD` 打印的路径

**重新审阅者返回：**逐条发现结论（ADDRESSED / NOT ADDRESSED）、修复差异中的新问题、范围外观察，以及本轮结论。
