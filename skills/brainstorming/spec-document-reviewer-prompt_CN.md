# 规范文档审阅者提示词模板

在派遣规范文档审阅子代理时使用此模板。

**目的：**验证规范是否完整、一致，并已准备好进入实现规划阶段。

**派遣时机：**规范文档已写入 docs/superpowers/specs/ 之后。

```
Subagent (general-purpose):
  description: "审阅规范文档"
  prompt: |
    你是一名规范文档审阅者。请验证该规范是否完整，并已准备好进入规划阶段。

    **待审阅规范：**[SPEC_FILE_PATH]

    ## 检查内容

    | 类别 | 检查项 |
    |----------|------------------|
    | 完整性 | TODO、占位符、“TBD”、未完成的章节 |
    | 一致性 | 内部矛盾、相互冲突的要求 |
    | 清晰度 | 需求是否存在歧义，可能导致实现者构建出错误的东西 |
    | 范围 | 是否足够聚焦，能够对应单个计划——而不是涵盖多个相互独立的子系统 |
    | YAGNI | 未请求的功能、过度工程化 |

    ## 校准标准

    **只标记那些会在实现规划期间造成实际问题的问题。**
    缺少某个章节、存在矛盾，或某项要求含糊到可能被理解成两种不同含义——这些才是问题。轻微的措辞改进、风格偏好，以及“某些章节不如其他章节详细”，都不算问题。

    除非存在会导致计划有缺陷的严重缺口，否则请批准。

    ## 输出格式

    ## 规范审阅

    **状态：** Approved | Issues Found

    **问题（如有）：**
    - [章节 X]：[具体问题]——[为什么这会影响规划]

    **建议（仅供参考，不阻止批准）：**
    - [改进建议]
```

**审阅者返回：**状态、问题（如有）、建议
