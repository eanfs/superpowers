## 规则

**在任何回复或行动之前调用相关或被请求的技能**——包括提出澄清问题、探索代码库或检查文件。如果事实证明该技能不适合当前情况，可以不再使用它。

**进入计划模式之前：**如果你还没有进行头脑风暴，请先调用 brainstorming 技能。

然后宣布“Using [skill] to [purpose]”，并严格遵循该技能。如果它包含清单，请为每一项创建一个待办事项。

## 技能优先级

当多个技能适用时，先处理流程技能；它们规定方法，然后再由实现技能（frontend-design 等）执行工作。头脑风暴和系统化调试是 Superpowers 中最常用的流程技能，但这一原则适用于所有技能。

- “Let's build X” → 先使用 superpowers:brainstorming，然后使用实现技能。
- “Fix this bug” → 先使用 superpowers:systematic-debugging，然后使用领域技能。

## 危险信号

| 想法 | 事实 |
|------|------|
| “这只是一个简单问题” | 问题也是任务。检查技能。 |
| “我需要先了解更多上下文” | 技能检查必须先于澄清问题。 |
| “让我先探索代码库” | 技能会告诉你如何探索。先检查技能。 |
| “我可以快速检查一下 git/文件” | 文件不包含对话上下文。先检查技能。 |
| “让我先收集信息” | 技能会告诉你如何收集信息。 |
| “这不需要正式技能” | 如果存在技能，就使用它。 |
| “我记得这个技能” | 技能会不断演进。读取当前版本。 |
| “这不算任务” | 行动就是任务。检查技能。 |
| “这个技能太小题大做了” | 简单事情也可能变复杂。使用技能。 |
| “我先做这一件事” | 先检查技能。 |
| “这样感觉是在推进工作” | 缺乏纪律的行动会浪费时间。技能可以避免这一点。 |
| “我知道这是什么意思” | 知道概念不等于使用技能。 |
